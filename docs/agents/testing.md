# Testing

## 변경 종류별 검증

- 변경 위험도와 관련 범위에 맞는 검증을 선택함. 모든 작업에 전체 테스트를 강제하지 않음.
- 문서만 변경하면 링크·명세 간 모순·관련 계약을 확인함. 코드용 typecheck나 build를 억지로 실행하지 않음.
- 코드 변경은 관련 테스트와 저장소의 실제 typecheck 명령으로 검증함. 최초 앱 구성과 빌드·라우팅·환경 설정 변경은 production build도 확인함.
- lint와 integration/E2E는 변경 영향과 저장소에서 정한 필수 검증에 따라 수행함.
- 실제 배포 origin의 인증 검증 적용 시점은 [계약 문서](../FRONTEND_CONTRACTS.md)의 배포·로컬 연동 항목을 따름.

## 실패·실행 불가·완료 판정

- 실패는 이번 변경의 결함, 기존 결함, 실행 환경 문제로 구분함. 이번 변경의 결함은 수정하고 재검증함. 관련 없는 기존 오류까지 무단으로 수정 범위를 넓히지 않음.
- 환경 때문에 필수 검증을 실행할 수 없으면 허용된 대안과 독립적인 구현을 진행함. 미실행 항목·원인·재실행 방법을 보고함.
- 실패한 관련 필수 검증이나 실행하지 못한 필수 검증이 남으면 전체 작업을 검증 완료로 선언하지 않음. 구현 완료 부분과 검증 차단 부분을 구분해 보고하며, 차단된 검증을 임의로 필수 항목에서 제외하지 않음.
- 실행하지 않은 검증을 성공으로 보고하지 않음. Mock으로 실제 DB·network·concurrency 특성까지 검증됐다고 판단하지 않음.
- 관련 검증이 통과했고 새로운 변경이나 우려가 없으면 같은 검증을 불필요하게 반복하지 않음.
- 커밋 가능 여부와 컴파일 또는 실행 가능 조건은 [git.md](git.md)를 따름. 검증 차단을 이유로 커밋 조건을 우회하지 않음.

## 프론트 검증 항목

아래 항목 중 변경한 흐름과 그 영향 범위를 검증함. 작은 변경마다 전 항목을 다시 실행하는 목록이 아님.

- 폼 오류, 로딩, 빈 결과, 재시도, 중복 제출 방지 등 화면 상태.
- 투표의 네 상태(가능·미정·불가능·미투표), 초기화 후 저장, 실패 시 편집본 보존, 편집 중 이벤트·마감·기간 변경.
- OAuth 콜백 중복 실행 방지, 복귀 경로, 새로고침 복원, Main/Participant별 401 처리, 회원·비회원 재입장.
- 소켓 재연결 후 재조회, 캘린더 이동 시 구독 해제, 삭제·강퇴와 일시적 끊김의 구분.
- 모바일 터치와 데스크톱 키보드 날짜 선택, 색상 외 상태 구분, 폼 라벨·모달 포커스·오류 연결.

자동 테스트 범위와 실제 브라우저·백엔드 확인 범위를 구분해 보고함. 실행 명령은 프론트 package scripts가 생기면 해당 README에 기록함.
