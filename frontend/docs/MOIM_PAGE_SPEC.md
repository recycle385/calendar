# moim 페이지 및 기능 명세

이 문서의 확인·동의·재시도 선택은 별도 언급이 없으면 앱 사용자의 화면 동작을 뜻한다. 해당 UI 구현을 시작하기 위한 에이전트 승인 요구가 아니다. 실제 데이터나 운영 환경을 변경하는 에이전트 작업의 승인 조건을 대체하지 않는다.

화면과 사용자 행동의 기준 문서다. 코드 배치는 [FRONTEND_ARCHITECTURE.md](FRONTEND_ARCHITECTURE.md), API·인증·저장·캐시·날짜 규칙은 [FRONTEND_CONTRACTS.md](FRONTEND_CONTRACTS.md)를 따른다.

## 0. 구현 범위와 결정 사항

- 현재 범위는 아래 사용자 페이지 중 U-05를 제외한 7개와 OAuth 콜백 처리 경로다.
- U-05 참여한 캘린더와 A-01~04 관리자 페이지는 요구사항을 보존하되 백엔드 확장 후 구현한다. 현재 메뉴·라우트에 노출하지 않는다. 임의 API나 가짜 운영 데이터로 완료 처리하지 않는다.
- 투표는 날짜별 가능·미정·불가능과 미투표를 구분한다. 명시적인 저장 버튼을 사용하고 시간 슬롯·자동 저장은 제공하지 않는다.
- 신규 사용자 가입은 pending/immediate 두 백엔드 응답을 처리한다. 가입 전 약관 확인이 필요한 배포는 pending 설정을 전제로 한다.
- 아래 후보 정렬·편집·복귀 규칙은 이번 문서 정리에서 정한 프론트 기본 동작이며, 백엔드가 제공하는 별도 정책 API가 아니다.

## U-01. 홈 `/`

| 상태     | 기능                                                                       |
| -------- | -------------------------------------------------------------------------- |
| 비로그인 | 서비스 소개, 생성 → 공유 → 투표 사용법, 스터디·회의·여행 등 정적 예시      |
| 비로그인 | Google 시작, `/login` 이동, 공유 링크 입력으로 참여 진입                   |
| 로그인   | 이름·프로필 표시, 내가 만든 최근 캘린더, 진행 중 요약, 생성·내 캘린더 이동 |

링크 입력은 현재 서비스의 `/c/:slug` 또는 `/c/:slug/join` URL을 확인해 내부 참여 경로로 이동한다. 다른 사이트의 URL로 자동 이동하지 않는다. 프로필 표시용 데이터가 없으면 기본 사용자 표시를 사용한다. 최근 목록은 생성일 내림차순으로 최대 3개를 표시하고, 진행 중 수는 내 목록의 `is_closed=false`로 계산한다. 전체 서비스 통계처럼 표시하지 않는다.

진행 목록 조회 실패는 해당 영역에 재시도를 제공하고 홈 전체를 로그인 실패로 처리하지 않는다. 생성한 캘린더가 없으면 생성 CTA를 제공한다. `/joined` 메뉴는 후속 기능 활성화 전 숨긴다.

## U-02. 로그인 `/login`

| 기능                | 동작                                               |
| ------------------- | -------------------------------------------------- |
| Google 로그인       | 복귀 경로 보존 후 백엔드 OAuth 시작 주소로 이동    |
| 기존 회원·즉시 가입 | 인증 성공 후 원래 내부 경로로 복귀, 없으면 홈      |
| 가입 대기           | signupToken 보존 후 `/signup` 이동                 |
| 이미 로그인됨       | 복원 완료 후 복귀 경로 또는 홈으로 이동            |
| 약관 링크           | 서비스에서 제공하는 이용약관·개인정보처리방침 링크 |

로그인 취소·실패 시 오류와 다시 시작 버튼을 표시한다. 약관 URL·본문은 서비스 제공 자료를 연결하며 임의로 내용을 완성하지 않는다. 서비스 자료가 아직 없으면 배포 전 필요한 항목으로 기록한다.

제외: 이메일·비밀번호 로그인, 비밀번호 찾기, Kakao 로그인.

## AUTH-CB. OAuth 콜백 `/auth/callback`

code/state 확인 → 쿠키를 포함한 백엔드 callback 요청 → 로그인 완료 또는 가입 대기로 분기한다. 처리 중에는 진행 상태를 표시하고 중복 요청을 막는다. code/state 누락·사용자 취소·교환 실패는 로그인 재시작으로 복구한다. 요청 중 URL과 토큰 보존 방식은 계약 문서를 따른다.

## U-03. 가입 완료 `/signup`

| 기능      | 동작                                                                                  |
| --------- | ------------------------------------------------------------------------------------- |
| 가입 안내 | Google 인증이 완료되었음을 표시. 가입 전 이름·프로필은 현재 응답에 없어 표시하지 않음 |
| 동의      | 이용약관·개인정보 필수 항목을 각각 확인                                               |
| 가입 완료 | 둘 다 동의하면 `{signupToken,isTermsAgreed:true}` 제출                                |
| 완료 이동 | 토큰·사용자 정보 설정 후 보존한 내부 경로 또는 홈                                     |
| 실패      | 입력 오류 표시 또는 로그인 재시작. 이미 소비된 토큰을 자동 반복 제출하지 않음         |

signupToken은 메모리에만 두므로 새로고침·직접 진입·토큰 만료 시 로그인 재시작을 안내한다. 별도 개인정보 동의 이력이나 가입 전 프로필 조회 API가 있다고 가정하지 않는다. 제출 중 버튼을 막는다.

## U-04. 내 캘린더 `/calendars`

| 기능    | 명세                                                               |
| ------- | ------------------------------------------------------------------ |
| 목록    | `GET /calendars/joined`의 내가 만들거나 계정으로 참여한 캘린더      |
| 필터    | 전체 / 진행 중(`is_closed=false`) / 마감(`is_closed=true`)         |
| 검색    | 제목·설명의 클라이언트 검색                                        |
| 정렬    | 이름순 / 최신순(기본) / 오래된순 / 최근 수정순. 동률은 slug로 안정적으로 정렬 |
| 카드    | 제목, 설명, 후보 날짜 기간, 현재 참여 인원, 참여 역할·프로필, 투표 마감, 상태 |
| 이동    | 상세 또는 `/calendars/new`                                         |
| 빈 상태 | 원본 목록이 비면 생성 CTA, 필터 결과만 비면 검색·필터 초기화       |

참여 역할·프로필은 `방장 · 내 계정`, `게스트 · 내 계정`, `게스트 · 별명` 중 하나로 표시한다. 조회 중 로딩, 실패 시 목록 재시도를 제공한다. 상세 이동 후 회원 기반 재입장으로 연결된 Participant Token을 복원할 수 있어야 한다. `is_closed=false`여도 서버가 투표 기간 종료를 응답하면 해당 투표는 막는다.

제외: 임시저장, 반복 일정, 북마크, 전체 사용자 캘린더 목록.

## U-05. 참여한 캘린더

별도 화면을 두지 않고 U-04 내 캘린더 목록에 통합한다. 홈의 최근 캘린더는 기존처럼 `GET /calendars/my`를 사용해 사용자가 직접 만든 캘린더만 보여준다.

## U-06. 캘린더 만들기 `/calendars/new`

| 입력                  | 검증                                                      |
| --------------------- | --------------------------------------------------------- |
| title                 | trim 후 필수, 1~100자                                     |
| description           | 선택                                                      |
| hostNickname          | trim 후 필수, 1~20자                                      |
| vote_start_date / vote_end_date | 유효한 YYYY-MM-DD, 투표 시작일 ≤ 종료일, 양 끝 포함 최대 366일 |
| start_date / end_date | 유효한 YYYY-MM-DD, 후보 시작일 ≤ 종료일, 양 끝 포함 최대 366일 |

생성 중 중복 제출을 막는다. 성공 응답의 calendar·participantToken을 저장하고 `/c/:slug`로 이동해 공유 링크 복사 안내를 제공한다. 공유 URL은 응답의 shareUrl을 우선 사용한다. 복사가 실패하면 URL 선택·수동 복사를 제공한다. 실패하면 입력값을 유지한다. 네트워크 결과 불명 상태에서는 생성 요청을 무조건 재전송하지 않고 내 목록 확인을 안내한다.

투표 가능 여부와 자동 마감은 `vote_start_date`와 `vote_end_date`를 기준으로 한다. `start_date`와 `end_date`는 참여자가 선택할 후보 날짜 범위다. `expired_at`은 사용자가 입력하지 않으며 서버가 `vote_end_date`에서 30일 뒤로 계산한다.

제외: 카테고리, 대표 이미지, 반복 일정, 추가 설정 단계, 임시저장.

## U-07. 캘린더 참여 `/c/:slug/join`

### 진입과 상태 확인

1. slug로 캘린더를 조회하고 제목·설명·기간·마감 여부를 보여준다.
2. 회원 인증·저장된 참가 세션을 복원하는 동안 대기 UI를 표시한다.
3. 유효한 해당 참가 세션이면 상세로 이동한다. Main 로그인만으로 참가 완료로 처리하지 않는다.
4. 세션이 없는 회원은 `GET /calendars/joined`로 계정에 연결된 참여를 확인하고, 이미 참여했다면 Main Token으로 참가자 login API를 호출해 바로 상세로 이동한다. 미등록이면 신규 참가 폼을 보여준다. 실패한 네트워크 요청을 미등록으로 간주하지 않는다.
5. 비회원은 닉네임과 비밀번호를 한 번 제출한다. 서버는 해당 캘린더에 닉네임이 없으면 신규 참가자를 만들고, 이미 있으면 비밀번호를 검증해 재입장시킨다. 틀린 비밀번호로 새 참가자가 생성되지 않는다.

캘린더가 없으면 찾을 수 없음 안내와 홈 이동을 제공한다. 마감된 캘린더는 신규 참여를 막되 기존 참가자 재입장은 허용해 결과를 볼 수 있게 한다.

### 회원과 비회원

| 구분        | 신규 참여                                      | 재입장                                        |
| ----------- | ---------------------------------------------- | --------------------------------------------- |
| 회원 계정   | Main Token + nickname + `profileType=account`  | Main Token + 빈 본문. 방장도 같은 재입장 흐름 |
| 회원 별명   | Main Token + nickname + `profileType=alias`    | Main Token + 빈 본문                          |
| 비회원      | nickname + 개인 password                       | nickname + 개인 password                      |

닉네임은 trim 후 1~20자, 비밀번호는 trim 후 4~50자다. 비밀번호는 캘린더 공용 비밀번호가 아니라 개인 재입장용이며 저장하지 않는다. 별도 비밀번호 복구 기능은 없다.

`alias`는 계정과 분리된 익명 참가가 아니라 표시 이름만 다른 계정 연결 참가다. 따라서 최초 참여와 재입장 모두 개인 비밀번호를 요구하지 않는다. 회원 등록 중 중복 참가 응답이면 기존 참가 확인 흐름으로 전환하고, 닉네임 충돌이면 입력 오류를 표시한다. 완료 후 응답의 참가자 UUID와 토큰을 해당 slug에 저장하고 상세로 이동한다. 비회원 참여 중 회원 로그인으로 전환하면 원래 slug로 복귀한다. 기존 비회원 참가를 회원 계정에 자동 연결하는 API는 없으므로 이를 약속하지 않는다.

## U-08. 캘린더 상세 `/c/:slug`

캘린더 정보, 공유 링크, 방장 표시, 마감 상태, 실시간 연결 상태를 공통 영역에 둔다. 직접 진입도 U-07의 참가 세션 확인 흐름을 거친다.

내부 탭은 `?tab=vote|status|participants|settings`로 표현하고 기본값은 vote다. 잘못된 탭 값은 기본 탭으로 정규화한다. 일반 참가자는 settings 탭을 볼 수 없고 직접 지정해도 기본 탭으로 이동한다. 탭 전환 자체로 소켓을 새로 만들지 않는다.

### U-08-1. 날짜 투표

| 기능           | 명세                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| 날짜           | 실제 날짜 옵션을 달력에 표시. 비활성 날짜는 선택 불가                                                  |
| 상태 선택      | 적용할 가능 / 미정 / 불가능 / 미투표 도구를 선택한 후 날짜 클릭·키보드 활성화로 적용. 기본 도구는 가능 |
| 내 투표        | 개인 투표 응답을 네 상태의 편집본으로 복원                                                             |
| 초기화         | 편집본만 전체 미투표로 변경. 저장 전에는 서버에 반영하지 않음                                          |
| 저장           | 미투표를 제외한 전체 `{votes:[{date,voteType}]}` 제출. 빈 목록 저장은 전체 취소                        |
| 저장 중        | 선택·중복 저장 차단. 완료 후 성공 표시                                                                 |
| 실패           | 편집본 유지, 오류와 재시도 제공                                                                        |
| 실시간 반영    | 조회 데이터 갱신. dirty 편집본은 덮어쓰지 않음                                                         |
| 마감·기간 변경 | 저장 중지 및 상태 재조회. 계약 문서의 편집본 처리 적용                                                 |

상태는 색상과 텍스트/아이콘을 함께 사용한다. 수정하지 않았으면 저장을 비활성화한다. 미저장 상태로 페이지를 떠나면 확인한다. 개인 투표 조회 실패를 빈 투표로 초기화하지 않는다. 모바일에서도 같은 상태 도구로 여러 날짜를 선택할 수 있게 한다. 시간 슬롯·자동 저장·드래그 전용 조작은 제공하지 않는다.

### U-08-2. 투표 현황

| 기능          | 명세                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| 날짜별 집계   | 가능·미정·불가능 인원 각각 표시. 미투표는 참가자 총수에서 해당 날짜 응답자 수를 뺀 값 |
| 참가자 확인   | 날짜별 상태별 응답자 이름 표시. UUID가 필요한 개인 조회는 참가자 목록을 사용          |
| 후보 순위     | 활성 날짜 중 가능 인원 내림차순 → 미정 인원 내림차순 → 날짜 오름차순, 상위 3개        |
| 후보 없음     | 가능·미정 응답이 하나도 없는 날짜는 후보에서 제외. 전체 후보가 없으면 안내            |
| 날짜 상세     | 선택한 날짜의 상태별 현황                                                             |
| 참가자별 조회 | 참가자 UUID로 개인 투표 조회                                                          |
| 실시간·마감   | 이벤트 후 최신 조회, 마감 후 읽기 전용 결과                                           |

불가능·미투표를 찬성 인원에 더하지 않는다. 후보 순위는 프론트 계산이며 최종 모임 날짜 확정·예약 기능은 아니다. 집계 데이터 일부가 로딩·실패 상태이면 미투표 수를 추측해 표시하지 않는다.

### U-08-3. 참여자

| 기능           | 명세                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 목록           | 현재 참가자, 닉네임, 참여일                                                          |
| 방장           | 참가자 uuid와 calendar.hostParticipantUuid를 비교                                    |
| 투표 수·투표율 | API의 vote_count / total_dates / vote_rate. 가능 인원 비율이 아니라 응답한 날짜 비율 |
| 온라인         | Socket 정보의 참고 표시. 네트워크 끊김·다중 탭에 대한 정확성 한계는 계약 문서 기준   |
| 개인 투표      | 참가자 선택 시 UUID로 조회                                                           |
| 나가기         | 일반 참가자 본인 탈퇴, 확인 후 Participant Token으로 요청                            |
| 강퇴           | 방장만, 대상 닉네임 확인 후 Main Token으로 요청. 방장은 강퇴 불가                    |

현재 total_dates는 비활성 날짜를 포함한 전체 옵션 수다. 화면에서 다른 분모를 만들어 같은 이름으로 표시하지 않는다. 탭 진입·포커스 복귀·관련 API 성공 후 목록을 갱신한다. 참가자 목록은 서버에 등록된 사람이고 온라인 목록과 다르다.

탈퇴 성공은 해당 slug 세션·개인 캐시·소켓을 정리하고 홈으로 이동한다. 강퇴 성공은 목록과 투표 현황을 재조회한다. 대상 사용자는 소켓 끊김만으로 강퇴를 확정하지 않고 최신 참가 상태를 확인한다.

### U-08-4. 설정

Main 로그인 및 현재 회원으로 확인한 방장 참가 상태에서 접근한다. 관리 요청의 최종 소유권 검증은 백엔드가 수행한다.

| 기능      | 명세                                                                   |
| --------- | ---------------------------------------------------------------------- |
| 수정      | 제목·설명·시작일·종료일. 생성과 같은 입력 제한을 최종 합쳐진 값에 적용 |
| 변경 저장 | 변경한 필드만 PATCH. 변경이 없으면 비활성화                            |
| 기간 축소 | 범위 밖 날짜와 해당 투표가 삭제됨을 저장 전에 확인                     |
| 공유 링크 | 복사 및 수동 복사 대안                                                 |
| 마감      | 확인 후 요청, 되돌리기 기능 없음                                       |
| 삭제      | 영구 삭제 확인 후 요청                                                 |

마감된 캘린더는 수정·저장·재마감을 막고 공유·삭제는 제공한다. 마감·삭제·강퇴·수정 요청에는 Main Token을 사용한다. 저장 중 중복 요청을 막고 실패 시 입력을 유지한다. 다른 방장 세션에서 변경·마감되면 최신 상태를 반영하고 저장 충돌을 안내한다.

## 2. 관리자 페이지 — 전체 후속 범위

관리자 인증·권한 모델, 목록·통계 API, 이용 제한 정책, 감사 기록 저장·조회가 현재 백엔드에 없다. 아래 route는 프론트 제안이며 현재 공개하지 않는다. 일반 사용자의 host 역할을 서비스 관리자로 해석하지 않는다.

| ID   | 페이지·Route                   | 확장 후 기능                                                                                                       |
| ---- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| A-01 | 대시보드 `/admin`              | 전체/최근 가입 사용자, 전체/진행/마감 캘린더, 참가자 수, 최근 투표량, 최근 사용자·캘린더·관리 활동, 관리 화면 이동 |
| A-02 | 사용자 관리 `/admin/users`     | 이메일/닉네임 검색, 정상/제한 필터, 가입일·최근 로그인·OAuth 정보, 생성/참여 수, 이용 제한                         |
| A-03 | 캘린더 관리 `/admin/calendars` | 전체 목록, 제목/생성자 검색, 상태 필터, 제목·생성자·생성일·상태·참가자 수, 운영 상세, 강제 마감·삭제               |
| A-04 | 운영 로그 `/admin/logs`        | 제한·마감·삭제 기록, 대상·작업자·시각, 유형·기간 필터                                                              |

관리자 기능 구현이 작업 범위에 포함될 때 각 API의 요청·응답과 관리자 권한, 제한이 실제 사용자 행동에 미치는 영향, 조치 기록 보존을 확정한다. 이 후속 계약의 미정 사항은 현재 사용자 화면 구현을 막지 않는다. 일반 사용자에게 전체 캘린더 목록은 제공하지 않는다. 공휴일 쓰기용 운영자 토큰을 브라우저 관리자 인증으로 재사용하지 않는다.

## 3. 공통 기능과 완료 기준

| 항목       | 명세                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| Responsive | PC·Tablet·Mobile에서 읽기·선택·저장 가능. 특정 hover·드래그에만 의존하지 않음                  |
| Loading    | 화면 영역에 맞는 Skeleton/Spinner. 인증 복원 중은 별도 상태                                    |
| Empty      | 실제 빈 데이터와 검색 결과 없음을 구분하고 필요한 CTA 제공                                     |
| Error      | 필드 오류/권한/찾을 수 없음/네트워크 오류를 구분. 입력 보존과 적절한 재시도                    |
| 인증       | Main·Participant·OAuth 오류를 계약 문서대로 구분. 모든 401에 refresh를 적용하지 않음           |
| Guard      | 로그인·캘린더 참가·방장 확인. 관리자 가드는 후속                                               |
| 서버 상태  | TanStack Query. 폼·투표 편집본과 분리                                                          |
| 폼         | React Hook Form + Zod. 실제 백엔드 입력 제한 반영                                              |
| 알림       | 저장 성공·실패 등 Toast. 폼 오류·접속 끊김처럼 지속적인 상태는 화면에도 표시                   |
| 확인       | 마감·삭제·강퇴·탈퇴·기간 축소·미저장 이탈에 Dialog                                             |
| 접근성     | 명시적 라벨, 색상 외 상태 구분, 키보드 날짜 조작, 오류와 필드 연결, 모달 진입·종료 포커스 복원 |
| 날짜       | 날짜 값은 그대로, timestamp는 KST 표시. 계약 문서 기준                                         |
| 재연결     | 상태 표시, 방 재입장 및 최신 데이터 조회. 편집본 보존                                          |

접근 불가한 route는 안내와 복구 경로를 제공한다. 뒤로 가기와 직접 URL 진입도 같은 가드·탭 규칙을 적용한다. 확인 Dialog는 취소하면 원래 입력·화면을 유지한다.

각 화면 완료 시 정상 흐름뿐 아니라 로딩·빈 결과·오류·권한 차이·모바일/키보드 조작을 관련 범위에서 확인한다. 테스트 상세는 [testing.md](agents/testing.md)를 따른다.

## 4. 현재 Route 구조

```text
/
├─ login
├─ auth/callback
├─ signup
├─ terms
├─ privacy
├─ calendars
├─ calendars/new
├─ c/:slug/join
└─ c/:slug?tab=vote|status|participants|settings
```

현재 사용자 화면 7개와 법적 고지 화면 2개 + OAuth 처리 경로 1개다. U-05 `/joined`와 A-01~04 `/admin...`는 백엔드 확장 후 추가한다. 상세의 투표·현황·참가자·설정은 별도 페이지가 아닌 내부 탭이다.
